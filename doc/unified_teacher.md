# 统一流程：特权老师（2026-11-11）

用户的新设计：一个带特权信息的老师，蒸馏出盲走和深度两个学生；验收要求直接写成训练约束；每次同时跑多个种子。这一步只做老师。全部是新代码：`src/tasks/velocity` 下的现有任务一行没改，rp6 / gp1 照常用它们训练。

## 文件

| 文件 | 作用 |
|---|---|
| `src/tasks/unified/robots.py` | 机型表（只有物理参数：负载上限和位置、墙前停距、足端半径），以及老师所用的底座环境 |
| `src/tasks/unified/teacher_env.py` | 老师环境：特权观测、奖励三分组、约束表、换上新课程 |
| `src/tasks/unified/curriculum.py` | 按表现推进的单次课程：进度 p，以及由它驱动的楼梯份额、指令范围、负载 |
| `src/tasks/unified/constraints.py` | 约束引擎（拉格朗日乘子）、楼梯计数计量项、自定义指标 |
| `src/tasks/unified/symmetry.py` | 镜像损失的左右对称映射（包含特权项） |
| `src/tasks/unified/runner.py` | 训练器：镜像损失；把进度、乘子、计量写进检查点，续训时恢复 |
| `src/tasks/unified/__init__.py` | 注册 `Unitree-<R>-U-Teacher` 和 `-Lean`（只在 `UNIFIED_TASKS=1` 时注册） |
| `scripts/unified/teacher_gate.py` | 老师是否通过：按训练中的约束读数判定 |
| `jobs/unified/teacher.sh` | 启动：多个种子并排或依次训练，最先通过的为选中 |

## 流程

1. **底座环境**（`robots.base_env_cfg`）：调用现有的盲走构建函数，地形是 map3，开关用统一配方 P 阶段的全部开关（去掉旧约束组和低熵），阶段取 T 的早期权重爬坡。这样机器人、地形、指令（停车、横移、原地转、踏步、急停后起步等情形）、随机化、负载、传感器、步态时钟和各个带状态的代价项，都和交付模型训练时完全一样。再套上深度老师的抬高高度扫描。构建时临时设好环境变量，构建完恢复，不影响同一进程里其他任务。
2. **特权观测**（`teacher_env._add_privileged`）：执行网络在 10 帧本体感觉和高度扫描之外，还能看到底盘线速度、足端高度、悬空时间、着地，以及随机化后的重心偏移、负载和地面摩擦。这些盲走学生都能从历史里推断出来。定点保持和漂移的锚点偏移只给评价网络，这样老师的「站稳不漂」是学生学得来的行为。
3. **奖励三分组**（`teacher_env._rewards`）：
   - 核心奖励，权重固定，Go2 18 项：速度跟踪、步态时钟、姿态、终止、平滑、关节限位、摆腿离地、上下楼进度、平地速度、腿的倾斜。
   - 约束代价，Go2 14 项：每项对应一个验收项，权重由约束引擎调。
   - 其他塑形项，Go2 10 项、Go2W 16 项：完整版保留原权重，精简版去掉（「奖励只留十来项核心」）。
4. **单次课程**（`curriculum.py`）：进度 p 取两者中大的一个：按地形等级算的（开局的平均等级到 50% 最高等级是 0 到 1），和时间保底（第 500 次迭代起，4000 次迭代从 0 到 1；楼梯以外地面上训练机器人的失败率超过 30% 时按四分之一的速度走）。平滑处理，只升不降。楼梯质量 q 见 `doc/redesign.md` 3.4。
   - 楼梯份额：p 到 0.3 之前是 8%，0.8 时升到 50%；其他地面里粗糙 36%、平地 54%、两种斜坡各 5%；
   - 指令范围：p 到 0.25 之前用初始范围，之后用最终范围；
   - 负载上限：p 从 0 到 0.5，0 kg 升到行走负载（Go2 / Go2W 8 kg）的一半；另一半跟着 q 加上去；
   - 约束：平地类在 p 0.15 开启；楼梯类跟着 q，q 从 0 到 1 把目标从宽松值收到门槛。
5. **约束引擎**（`constraints.constraints`）：
   - 每项有测量、目标、方向（不低于 / 不高于）和它调节的代价项；
   - 测量值平滑后和目标比较，没达标乘子上调，达标了回落，范围是原权重的 0.5–3 倍；
   - 多个约束调同一项时取最大的倍数；
   - 下限大于 0，因为权重为 0 的项会被跳过，带状态的项就不再更新。
6. **测量**：
   - 验收本身测的项（步态时钟、漂移、后退偏差、停车蠕动、踏步漂移、原地转、楼梯速度、腿碰地、踩边、四轮着地、慢弧线），沿用 `mdp.constraints` 里已对着验收校准过的算法。
   - 楼梯计数（滑回、踢立面、顶部平台空中时间、起步空踏）由计量项累计成「每上一级台阶多少次」。
   - 门槛取已交付那一版在训练环境里的水平：Go2W g27b、As2W a1f、B2 l10。训练环境比验收难，所以数值比 tinynav 的高。
7. **训练器**（`runner.py`）：
   - 镜像损失和原来一样，特权项的左右映射在 `symmetry.py` 里；
   - 足端接触力是世界坐标的，镜像要看偏航角，所以只给评价网络；
   - 每个检查点都带上进度、乘子、测量值和计量累计，续训时恢复，不会再出现乘子回到 1 倍的问题。
8. **判定和选种子**：
   - `teacher_gate.py` 在每个检查点（每 100 步）看最近 500 步：进度是否一直为 1，所有执行中的约束是否都达标；
   - `teacher.sh` 每 15 分钟判一次所有种子，最先通过的写进 `logs/jobs/unified_<r>_<variant>.pick`，其余种子停掉。

## 用法

```
# 训练机上（t1 / t2）：Go2 完整版，种子 0、1 并排，各 2048 台
PARALLEL=1 bash jobs/unified/teacher.sh Go2 full "0 1"
# 冒烟：几十步，进度强制推进，让每个开关都走一遍
U_SMOKE=1 bash jobs/unified/teacher.sh Go2 full 0 40
```

## 负载：重载奖励组 + 轻载约束（2026-11-11）

用户定的方案：物理参数不动，带负载的几项按「奖励引导 + 验收只记录」。

- **轻载约束**：停车蠕动、原地踏步漂移、横移 / 直行跑偏、交替原地转，只统计轻载（当时是负载 ≤ 3 kg，11-12 起是负载上限的 25% 以下，见下面「老师 v2」）的机器人（`u_stand_hold_light`、`u_drift_light`、`u_spin_light`），对着无负载的验收门槛，乘子照旧。
- **重载奖励组**：`u_heavy_creep`、`u_heavy_march`、`u_heavy_side_drift`、`u_heavy_straight_drift`、`u_heavy_spin`（`constraints.heavy_group`）。重载（当时是 ≥ 8 kg，11-12 起是负载上限的 2/3 以上）的机器人，这几项的代价固定按配方的原始权重算，不受乘子影响；不设门槛，不加压。
- **记录**：`Curriculum/u_heavy/<项>/{light,heavy,gap}`，看重载和轻载差多少、差距是否在缩小。
- **验收**：同一组考题再加跑一遍负载上限，结果写进 `<P>_payload_gap.txt`（`scripts/blind/acceptance/payload_gap.py`），只记录，不判。

## 老师 v2（2026-11-12，doc/redesign.md 3.5）

- **遮挡扫描模式**：40% 的回合把老师的地形扫描清零，同时给一个「看得见 / 看不见」标志（`scan_flag`，actor 和 critic 都有）。`U_SCAN=on / off` 可以固定（评估、学生蒸馏用）。
- **特权信息压缩**：特权项单独成一个观测组 `actor_priv`，经 `models.UPrivLatentModel` 的小编码器（64 → 8）压成 8 维向量再进策略网络。ONNX 导出时输入是普通观测在前、特权在后。
- **楼梯约束用共享指标**（`src/metrics`，和 tinynav 同一套计数）：腿式按每走一级计——踢立面 ≤ 0.245、打滑 ≤ 0.0245，落脚居中 ≥ 80%、踩边 ≤ 10%；轮式滑回 ≤ 5%。轮式的起步和顶部平台空踏暂用原计数。门槛由 tinynav 每趟门槛按每趟 8.15 级换算。
- **轻载 / 重载**：按负载上限的比例划分，≤ 25% 为轻载，≥ 2/3 为重载。负载上限是官网行走负载（Go2 / Go2W 8 kg）。
- **关节静摩擦和阻尼随机化**：每个关节的静摩擦在 0 到力矩上限的 2.5% 之间，阻尼按宇树 As2 的比例取并放宽到 1.5 倍。
- **PPO 熵系数**（2026-11-12）：轮式 0.005（就是盲走配方的 `lowent`，以前所有轮式机型从零训练都用这个值），腿式 0.01。Go2W 老师 v2 用 0.01 时，动作噪声到 1200 步涨到 1.22，85% 的回合因小腿 / 大腿碰地结束；同样的对齐模型上，已部署的 Go2W 盲走策略不碰地，所以问题不在模型，在探索噪声。
- **任务优先**（2026-11-12）：摔倒或非法接触的回合超过 30% 时，所有约束乘子停止加码，已高于 1 的每次更新回落 lr，回到 1 为止；和保底时钟在失败时放慢是同一个思路。日志 `Curriculum/u_constraints/relaxing`。起因：Go2W 老师 v2 有 6 个乘子顶在 3 倍（跑偏、停车蠕动、原地踏步、四轮着地）而达不到，动作噪声 0.75 → 1.08、摔倒率 26% → 65%、地形等级 2.5 → 0.6。
- **乘子步长**（2026-11-12）：每次更新最多变化 lr（差距按目标归一化后截在 ±1）。原来目标很小的项（停车蠕动 0.009 m）差距会被放大好几倍，十几次更新就顶到 3 倍。
- **熵系数统一 0.005**（2026-11-12）：腿式也用 0.005。Go2 的平地约束收紧后，动作噪声从 0.66 涨到 1.05、摔倒率从 10% 升到 46%；以前所有从零开始的盲走训练用的都是 0.005（`lowent`）。
- **楼梯和其他地形各有一个难度行**（2026-11-12）：每台机器记两个行号，楼梯列用 `stairs`，其他列用 `other`；回合结束时升降的是刚走过那一类的行号，下一回合抽到哪一类就用哪一类的行号。日志 `Curriculum/u_stairs_share/stairs_level`、`other_level`，随检查点保存和恢复；进度 p 的等级部分取两者的平均。起因：原来只有一个行号，平地上升到 3 行以上的机器被抽到楼梯时直接面对同一行的台阶（约 10 cm 以上）。Go2W 在 2300 步时上楼梯的回合 100% 以下巴（机身前端碰撞球）撞立面结束，下楼梯 55–88%，平地只有 6%；Go2 在 5900 步时楼梯约 50%，平地 3%。和负载无关（楼梯上轻、中、重载的失败率都是 97% 左右）。
- **失败定位工具** `scripts/unified/fail_probe.py TASK CHECKPOINT`：按训练的环境和课程跑策略，按子地形列出回合失败率、摔倒 / 非法接触次数和碰地的部位，并按负载和指令分类。 加 `--sample` 用训练时的带噪声动作跑；末尾列出各约束在这次运行里的读数、检查点里训练的读数、目标和乘子。两种动作各跑一遍，就能看出一项读数里有多少是探索噪声造成的。
- **评估机器人**（2026-11-12）：每个种子最前面 1/8 的机器人（2048 台里 256 台）用策略的均值动作、不加探索噪声，所有约束（包括楼梯计数和轻载 / 重载记录）只在它们身上测量。它们不参与 PPO 更新：优势置 0，价值目标取评论家原来的值，其余机器人的优势在自己之间归一化。`U_EVAL_ENVS` 改数量，0 为关闭；日志 `Curriculum/u_constraints/eval_envs`、`Curriculum/u_progress/fail_rate_eval`（评估机器人的失败率；时钟和乘子放松看什么见下一条）。检查点里的楼梯计数如果是按全体机器人记的，续训时从零重新累计。起因：验收看的是不加噪声的策略，约束目标也是按盲走后期阶段（噪声约 0.3）标定的；老师学楼梯时噪声在 0.5–0.7，带着噪声量出来的值达不到它其实已经达到的目标。Go2 老师 6400 步，均值动作 / 带噪声动作：停车蠕动 0.021 / 0.042 m（目标 0.008）、原地踏步漂移 0.036 / 0.060（0.04）、直行跑偏 0.059 / 0.068（0.06）、步态时钟 0.87 / 0.77（≥ 0.85）、楼梯停车四脚着地 0.86 / 0.49（≥ 0.6）。四个乘子因此顶到 3 倍，而加大惩罚并不能把噪声造成的读数压下来，结果奖励 28 → −3、噪声 0.48 → 0.69、失败率 8% → 17%。
- **评估机器人站固定的楼梯行**（2026-11-12，`curriculum.eval_rows`）：评估机器人在楼梯列上不跟课程升降，按编号平均分到验收范围内的行（台阶低于 18 cm 的行，现在的地形是 0–8 行，256 台时每行约 28 台，可见 / 遮挡各半）；楼梯以外的地面照旧跟课程走。上楼、下楼各按行记失败率，各行取平均得到 `env.u_eval_fail`（日志 `Curriculum/u_stairs_share/eval_up_fail`、`eval_down_fail`；记录里 `cur.eval_fail`、`eval_fail_rows`；TensorBoard `Diag/eval_fail/<up|down>_row<行>`；随检查点保存和恢复）。用在三处：楼梯类约束的放松看它（超过 30% 放松，低于 25% 恢复；其他地面的约束看训练机器人在其他地面的失败率）；楼梯约束的读数因此来自验收范围内的台阶，不再混进 18–20 cm 的行；记录里楼梯地面的「失败率过半」告警按它判（q ≥ 0.5 起），`relax:<类别>` 只在该类有约束已开启时才报。训练机器人的行数和失败率统计不含评估机器人。质量 q 只看训练机器人的上楼行（≥ 3.0）；进度时钟的减速只看楼梯以外地面的失败率。起因：地形课程把每台机器升到它会摔的那一行为止，所以前沿行上的楼梯失败率约 0.6，和策略能爬多高无关（Go2 老师 03c9c04，8000–10800 次迭代：楼梯占比 0.27 → 0.43，全部失败率 0.20 → 0.32，其他地面 0.05–0.1，楼梯约 0.6，楼梯行 3.4–4.35）。原来 q 的条件（上楼失败率 ≤ 30%）因此永远不满足，楼梯约束会一直放松；楼梯占比到最终的 0.65 时全部失败率约 0.41，进度时钟会从 p ≈ 0.55 起一直按四分之一速度走。开始进质量阶段时固定行的失败率多半还在 30% 以上（高行还没爬过），这时楼梯乘子不往上加、奖励按 q 换到 P 值；等评估机器人在验收范围内的失败率降到 25% 以下，乘子才开始收紧。长时间不降：看 `relax:<类别>` 告警和各行的失败率。

## 11-12 评审后的修改（从零重训用的版本）

- **负载安装点**：训练时从机型表的 `payload_point` 盒子里取（Go2 / Go2W：x ±0.25、y ±0.12、z −0.05 到 +0.30 m）；用户不知道负载最后装在哪里，范围尽量大。`teacher_env._payload_point`。检查环境的负载位置不变。
- **斜坡**：其他地面里加 `slope_down`（坡顶出发）和 `slope_up`（坑底出发）两列，各占其他地面回合的 5%，坡度随难度行从 0 到 0.25。约束和轻载 / 重载记录不统计斜坡上的机器人（`constraints.off_slopes`）。`teacher_env._add_slopes`。
- **静摩擦大于动摩擦**：`stick_slip.py`，每个控制步按接触点的滑动速度切换每只脚（轮）的摩擦系数，比值 1.0–1.3（`U_STICK_RATIO=lo,hi` 改，`1,1` 关闭）。训练和检查环境都有。评价网络和特权观测里的摩擦仍是随机化的那个系数（两者的几何平均）。
- **时间保底**：第 500 次迭代起、4000 次迭代；q 1000 次迭代（原来 1500 / 10000 / 2000）。
- **`metrics/mj.py` 的轮心顺序**：以前按传感器配置里写的顺序（FR FL RR RL）取轮心，传感器实际给的是机器人模型里的顺序（FL FR RL RR），左右取反了。只影响轮式起步空踏的两个读数（起跳位置、最高点），这两项只记录、不判。

## 看一次训练（2026-11-12）

用户要求：只看训练记录就能知道训练哪里出了问题，而且两三个小时内就要看出来。

| 看什么 | 怎么看 |
|---|---|
| 曲线 | `tools/go2_depth/monitor/tb.sh`（`--since "2026-11-12 20:00"` 只看之后的训练，`--stop` 关掉）；t1 在 `localhost:16061`，t2 在 `localhost:16062` |
| 哪里有问题 | 训练机上 `$PY scripts/unified/run_report.py <run 目录>`：按严重程度列出问题和依据（`--all` 列出每类地面，`--json` 给程序读） |
| 现在的状态 | `<run>/records/status.json`，每 10 次迭代重写：迭代、p、q、失败率、动作噪声、当前告警、参考节点到没到 |
| 所有训练是否卡住 | `python3 tools/go2_depth/monitor/progress_watch.py`：迭代不动、p 不涨、GPU 空闲，以及每个种子记录里的告警（`ALERT`）、记录自身故障（`FAULT`）、没有结束事件而状态过期（`DEAD`）、异常结束（`ENDED`） |
| 回合为什么失败 | 记录里每类地面按结束原因、碰地部位、负载档和位置、指令、遮挡模式分的计数；还不够就 `scripts/unified/fail_probe.py TASK CHECKPOINT` |
| 卡死在哪 | `kill -USR1 <训练进程号>`，各线程的调用栈写进 `<run>/records/crash_traceback.txt`，训练不停 |

记录文件（`src/tasks/unified/diagnostics.py`）：`timeline.jsonl` 事件、`record.jsonl` 每 20 次迭代一条快照、`status.json`、`crash_traceback.txt`。记录出错不会停训练（写一条 `fault` 事件，那一部分关掉）；`U_RECORDS=0` 全部关掉。

告警（只记录，不影响训练）：

| 告警 | 含义 |
|---|---|
| `late:<节点>` | 参考节点到时间没达到（`doc/redesign.md` 3.4 的表） |
| `fail_high:<地面>` | 第 800 次迭代后，某类地面一半以上的回合失败 |
| `payload_fail:<地面>` | 某类地面上带负载（中、重）的比轻载的多失败 10% 以上 |
| `std_high`、`std_rising` | 动作噪声超过 1.0，或 300 次迭代里涨了四分之一 |
| `cap:<约束>`、`relax:<类别>` | 乘子顶在上限；某类地面失败太多、已开启的约束在放松（楼梯看评估机器人的固定行） |
| `clock_slow`、`q_waiting`、`q_stalled` | 时钟按四分之一速度走；p 过了 0.5 而 q 还没开始；q 300 次迭代没动 |
| `torque_sat:<关节组>` | 某组关节 20% 以上的力矩顶在上限 |
| `eval_gap` | 全体机器人比均值动作的机器人多失败 20%：是探索噪声在摔 |
| `level_falling`、`len_drop`、`no_episodes:<地面>`、`unmeasured:<约束>` | 地形等级回落、回合变短、某类地面没有回合结束、某项约束没有新读数 |
| `nonfinite`、`nan_resets`、`value_loss_spike`、`ev_low`、`lr_floor`、`action_clip`、`fps_drop` | 数值和优化器方面的异常 |

发现问题后：改新代码，从出问题之前的检查点续训（`RESUME_AT=<迭代>`，单个种子用 `RESUME_AT_<种子>`）。
