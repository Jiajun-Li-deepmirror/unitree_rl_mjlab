# 验收与训练配方重新设计（2026-11-12）

用户 2026-11-12 同意的设计。主线不变：先训练一个特权老师，再蒸馏出盲走和感知两个学生。改动在老师的训练方式、
验收的结构和统计方法上。旧流程（`doc/acceptance.md`、`jobs/blind_chain.sh`、`jobs/fe_chain.sh`）保留，供已交付的
模型复现和重判用；新流程的代码另起，不在旧代码上改。

## 1. 为什么改

1. **配方越堆越多**：Go2 的 P 阶段有 35 个开关，大多是出了某个症状补的一项。精修链（gp1→gp2→gp3）一直在追一个
   不过的项目，补上又带坏别的。
2. **mjlab 预测不了 tinynav**：同一个指标两边量法不一样（踢立面），带负载的楼梯只在最后一步测，所以失败总出在最后
   （gp3：mjlab 基本全过，tinynav 空载上楼踢立面 8.4 次/趟、带 12 kg 下楼 6/6 摔倒）。
3. **统计噪声大**：每个种子单独判、样本少，只好用运气规则兜底。
4. **物理不准**：模型参数原来没和 unitree_ros 对齐（2026-11-11 已对齐，`doc/robot_params.md`），没有关节摩擦。
   真机最在意的低速项（蠕动、站姿、复位）恰恰对这些最敏感。
5. **从看得见的老师蒸馏看不见的盲走，本身有缺陷**：老师能提前看到台阶，盲走学生不能，学到的是平均动作，也就是
   更容易踢立面。

## 2. 验收

### 2.1 原则

- **一份规格表，一套量法**。每一项写清楚：条件（空载 / 负载、地形）、指标（只有一个函数实现）、门槛、样本量和
  判法、门槛的来源（官网规格 / 真机实测 / 暂定）。训练中的约束、mjlab 验收、tinynav、真机日志，都调用同一个指标
  函数（`src/metrics/`）。
- **分三层，能早测的不留到后面**：
  1. 训练中：每个检查点自动算全部指标的估计值，不达标的不进入下一层；
  2. mjlab 正式验收：3 个种子合在一起判；
  3. tinynav（对齐后的模型）和真机短流程：最终判定。真机由用户跑，完整记录，用同一套指标函数算，结果也用来
     标定仿真门槛。
- **两种条件**：空载 = 负载固定 0 kg，并关掉机身质量随机；负载 = 行走负载，放在机身前 0.15 m、上 0.20 m
  （B2 / B2W 上 0.30 m），同样关掉机身质量随机。
- **负载上限**统一为官网的行走负载，训练和验收都用：Go2 8 kg、Go2W 8 kg、As2 15 kg、As2W 16 kg、B2 40 kg、
  B2W 40 kg。
- **每份报告写明评估时的随机化范围**（两种条件相同，读数可直接对比）：足端摩擦 0.3–1.6、机身质心偏移 ±5 cm、
  PD 增益 ×0.85–1.15、编码器偏差 ±0.015 rad、执行延迟 0–4 个仿真步、初始关节偏移 ±0.1 rad、观测噪声，以及
  关节静摩擦和阻尼（见 3.3）。
- **没有运气规则**。通过 = mjlab 三个种子合并全部通过，加上 tinynav 全部通过。

### 2.2 mjlab 验收（3 个种子合并）

| 项目 | 空载 | 负载 |
|---|---|---|
| 平地速度（44 条指令） | 实际 / 指令在 80–120% | 不测 |
| 跑偏（直行、横移 10 s） | 航向 p50 ≤ 3°、p10 / p90 ≤ 8°；横向偏移 ≤ 行进距离的 5% | 对比读数，不判 |
| 原地旋转（±0.5 / 1.0 / 1.5 rad/s） | 终点离起点 p90 ≤ 0.2 m | 不测 |
| 交替原地转 | 终点离起点 p50 ≤ 0.25 m | 对比读数，不判 |
| 停车 | 站稳后抬脚 ≤ 1%、蠕动 ≤ 1 cm、从 1.0 m/s 刹停 ≤ 30 cm | 蠕动：对比读数，不判 |
| 原地踏步 | 每只脚每秒落地 ≥ 0.5 次、髋复位 ≤ 2°、漂移 ≤ 5 cm | 漂移：对比读数，不判 |
| 步态节奏 | 判定的指令全部合拍 | 不测 |
| 零指令站姿（合并原来的负重站立和负载急停后站姿） | 静站 60 s，以及从 1.5 m/s 急停后站 3 s：腿关节偏离默认站姿 p90 ≤ 0.15 rad | 同左 |
| 楼梯（5–18 cm 每档上、下各 75 台） | 到达率：有操作员 ≥ 95%、无操作员 ≥ 90%；速度 0.8–1.2 倍；停稳 ≥ 95%；停住四脚着地 ≥ 90%（固定值，不再和部署版比）；踢立面、打滑按每上一级计数（量法同 tinynav，门槛由 tinynav 门槛换算，用一个模型在两边各量一次核对后定）| 0 摔 |
| 四轮着地（轮式） | ≥ 98% | 不测 |
| 摔倒 | 以上空载测试全部 0 摔，包括急停后再起步 | 楼梯、零指令站姿 0 摔 |

### 2.3 tinynav 验收（对齐后的模型）

| 项目 | 空载（0 kg，每条路线 4 趟） | 负载（行走负载，前角点） |
|---|---|---|
| 腿式楼梯（map3 加金字塔） | 踢立面 ≤ 2 次/趟、落脚居中 ≥ 80%、踩边 ≤ 10%、打滑 ≤ 0.2 次/趟、0 摔 | 每条路线 10 趟，摔倒率的 95% 上界 ≤ 5%（60 趟 0 摔）；摔 1 次就补到每条 16 趟（96 趟，不能再摔） |
| 轮式楼梯 | 滑回 ≤ 5%、起步平台空踏 ≤ 0.5 次/趟、上楼航向偏差 ≤ 3°、顶部平台踏步 ≤ 1.0 次/趟、滑回门 ≤ 5%、0 摔 | 摔倒率同上，加滑回 ≤ 5% |

### 2.4 删除的内容

运气规则；停住四脚着地「不低于部署版」的对照表；只记录的项目（髋外展力矩，楼梯的停后漂移、腿碰台阶比例、到达
距离，tinynav 的横滚、map3 18 段的通过情况、上楼姿态，B2 在 x 0.30 角点的 40 kg 测试，tinynav 带负载时的踢立面
和打滑读数）；从来没测过的「抗推」列。

### 2.5 按建议值执行、用户可改的项（2026-11-12）

1. 停住四脚着地每档 ≥ 90%。参考：部署版 go2_blind_v4 下楼 0.71–0.87，gp3 0.75–0.90。
2. 三个种子合并后仍判 0 摔。
3. 负载下的四项（跑偏、停车蠕动、交替原地转、踏步漂移）保留为对比读数，不判。
4. tinynav 负载：每条路线 10 趟，摔倒率的 95% 上界 ≤ 5%（60 趟 0 摔）；摔 1 次就补到每条 16 趟（96 趟，不能再摔）。
   （11-12 用户授权学生那边的对话修改：减少验收耗时、减少靠运气通过；原来是「摔倒率 ≤ 5%、至少 40 趟」。
   统计方法见 `doc/accept_bars.md`。）
5. 零指令站姿空载、负载都判。
6. 急停后再起步时的摔倒计入 0 摔。

## 3. 训练配方

### 3.1 一个任务定义，加一张机型表
腿式、轮式各一份任务。机型之间的差别只在 `src/robot_table.py`：物理参数、负载、增益。不再有某个机型专用的开关；
任何新开关都要先在一个种子上做对照实验，证明有用才进配方。

### 3.2 奖励只留核心项，验收项写成约束
核心奖励：跟踪、步态节奏、姿态、平顺、抬脚、终止。约束用验收的指标函数。约束的实现在 Go2 上比较两种：现在的
拉格朗日乘子，以及「违反约束就按概率提前结束这一回合」（CaT），选结果好的那个。

### 3.3 物理
对齐的模型（`model=uros`），加上对未知参数的随机化：关节静摩擦（每个关节 0 到该关节力矩上限的 2.5%，按宇树
As2 数据的比例推出）、关节阻尼（参照 As2 的 0.2 / 0.5）、转子惯量。拿到真机实测后，把范围收窄到实测值附近。

### 3.4 课程
按表现推进，加时间保底（统一老师现在的做法）。地形难度、指令范围、负载、随机化范围，都按同一个进度往上加。

楼梯质量单独一段（11-12 加，代码已写、尚未测试）：进度 p 主要由时间推动，Go2W 老师到 p 0.70 时还完全不会上楼
（上楼梯回合 95–100% 失败，5 cm 台阶也一样：不抬轮直接撞第一级立面）。原因是楼梯质量项（台阶附近抬轮 4 倍
罚、磕立面 / 滑回 / 空踏 / 顶部平台罚、上楼速度 6 倍罚等）从第 0 步就全开，楼梯约束又在 p 0.5 按时间打开。
现在改成：
- 开训时奖励取配方 M 阶段的值（学会爬楼时用的那一套），楼梯约束关闭；
- 楼梯难度行分成上楼、下楼、其他三行；训练机器人上楼行的平滑均值 ≥ 3.0 时，「楼梯质量」q 开始走，1000 次迭代
  从 0 到 1，只进不退（11-12 起不再要求上楼失败率 ≤ 30%，原因见下）；
- q 从 0 到 0.5：奖励权重和参数从 M 值过渡到 P 值；q 从 0 到 1：楼梯约束的目标从宽松值收到验收线；
- 老师通过的条件加一条：q = 1。
- 评估机器人（按均值动作的 1/8）在楼梯列上不跟课程升降，平均分到验收范围内的固定行（台阶低于 18 cm 的 0–8
  行）。它们在固定行上的失败率决定楼梯约束放不放松（超过 30% 放松，低于 25% 恢复），楼梯约束的读数也来自这些行。
  起因（11-12，Go2 老师旧代码的数据）：地形课程把每台机器升到它会摔的那一行为止，前沿行上的楼梯失败率约 0.6，
  和策略能爬多高无关。按原来的条件 q 永远不会开始，楼梯约束会一直放松；楼梯占比到 0.65 时全部失败率约 0.41，
  进度时钟也会从 p ≈ 0.55 起一直按四分之一速度走。细节见 `doc/unified_teacher.md`。
平地约束仍按 p。腿式、轮式同一套代码（差异项从配方的 M / P 两套环境自动对比得出）。

时间保底加快了（11-12，为了快速迭代）：从第 500 次迭代起，4000 次迭代把 p 从 0 推到 1（原来是 1500 起、10000
次）；楼梯以外地面的失败率超过 30% 时按四分之一的速度走。旧时钟下 Go2 老师 800–1000 次迭代就会走平地，之后 4000 次迭代都在
等时钟。按新时钟，一次训练应当到达的节点（`diagnostics.expectations()`，晚了记录里报 `late:*`）：

| 迭代 | 应当看到 |
|---|---|
| 1000 | 平地会走（失败率 ≤ 30%） |
| 2500 | 指令范围切到最终值（p ≥ 0.25）；低行楼梯（0–2 行）上评估机器人的上楼回合一半以上成功 |
| 3500 | 上楼行 ≥ 1.5 |
| 4500 | 训练机器人的上楼行 ≥ 3（q 开始走） |
| 5500 | p = 1 |
| 6500 | q = 1；之后 500 次迭代全部约束达标即通过（最早约 5500–6000 次迭代，约 6 小时） |

### 3.4.1 负载安装点、斜坡、静摩擦（11-12）

- **负载安装点范围放大**。用户：「负载的重心偏移可以尽可能的大一些，因为我也不知道之后整机上会装在哪里」。Go2 /
  Go2W 训练时安装点在机身坐标 x ±0.25 m、y ±0.12 m、z −0.05 到 +0.30 m 的盒子里均匀取（原来 x ±0.15、y ±0.08、
  z 0–0.20）；8 kg 在 x 0.25 的力矩（2.0 kg·m）等于早先 12 kg 在 0.15。重载机器人里仍有 30% 放在盒子前端或后端
  的顶部、取 6–8 kg。机型表 `payload_point`，只用于新流程；验收的负载位置（前 0.15、上 0.20）不变。记录里按负载
  位置分的失败率（`run_report.py`）两三个小时内就能看出极端位置是不是在摔，摔就收窄。
- **斜坡**。用户：「斜坡可以稍微加一点，你定」。其他地面里加两种斜坡格：坡顶出发往下走、坑底出发往上走，各占
  其他地面回合的 5%，坡度随其他地面的难度行从 0 升到 0.25（沿轴线 14°，最陡处 16°）。没有验收项：约束不在斜坡
  上测量（代价项照常起作用），记录里斜坡是单独的两类地面，只看失败率。
- **静摩擦大于动摩擦**。用户：「模拟静摩擦大于动摩擦」。每台机器人每回合取一个比值 r = 静 / 动，1.0–1.3 均匀；
  每个控制步按每只脚（轮）接触点沿地面的速度切换它的摩擦系数：停住时 μ·√r，滑动时 μ/√r（μ 是原来随机化的
  系数，是两者的几何平均）。滑动一旦开始就比原来滑得更远。训练环境和 mjlab 的检查环境都有；tinynav-sim 没有。
  `U_STICK_RATIO=1,1` 关掉。记录里有「着地的脚在滑动的占比」。代码 `src/tasks/unified/stick_slip.py`。

### 3.5 老师：「看不见」也是老师会的
- 训练时一部分回合把地形扫描遮掉，同时给老师一个「看得见 / 看不见」的标志。同一个老师学会两种走法：遮掉时靠
  本体感觉抬高脚、试探台阶；看得见时提前规划落脚。
- 盲走学生蒸馏「看不见」模式，感知学生蒸馏「看得见」模式。
- 特权物理信息（负载、摩擦、质心等）先压成一个很小的向量再进网络，学生从自己的历史里估这个向量。

### 3.6 学生：先蒸馏，再强化学习微调
1. 学生自己走，老师给每一步打标签（DAgger）。
2. PPO 微调，加一项「别偏离老师太远」的约束。
感知学生训练时，深度图加上真实相机的噪声、延迟和安装位置误差。

### 3.7 多种子
老师每次 2 个种子同时跑，第一个过训练中判定的就是老师，另一个停下但保留。每个学生只验收一个候选：第二阶段最后
8 个检查点的平均。不过就用另一个老师种子重训学生（`students.sh` 自动回退）；两个种子都不过就停下，交给人看。
（11-12 改，原来是「第一个过三层验收的就用」：逐个检查点去试验收，等于多抽几次签。）

快速迭代时老师可以只跑一个种子（一台 GPU 一个种子更快）；配方过了训练中判定，再补第二个种子。

## 4. 流程
- 正式训练前跑冒烟测试：训练几十步、导出、过一遍 tinynav，整条链路通了再开大训练。改代码之后不逐次做冒烟，
  只在正式开训前做一次最快的（用户 11-12）。
- 每个机型一组参考曲线，偏离参考或长时间不动就报警，并自动收集固定的一组诊断数据。
- 不过就改配方，从改动所在的最早阶段重跑；改什么、为什么，写进配方代码。

### 4.1 最终目标和快速迭代（用户 11-12）

最终的模型要过验收：平地全向移动、原地踏步、上下楼梯；在楼梯上停下时四脚着地。带负载时动作和能力尽量和空载
一样，物理上做不到的不强求，但带负载一定不能摔。训练配方和课程由训练这边定，只有训练目标怎么表述不确定时才问
用户（硬件固定的参数和扰动参数不用问）。

一个版本有没有问题，要在两三个小时内从训练记录里看出来，不能等六个小时：

1. 每次训练都写记录（`<run>/records/`：`status.json` 每 10 次迭代、`record.jsonl` 每 20 次迭代、`timeline.jsonl`
   记事件）。`python scripts/unified/run_report.py <run>` 读记录，列出问题和依据；`tools/go2_depth/monitor/tb.sh`
   开 TensorBoard（t1 `localhost:16061`、t2 `16062`）。
2. 对照 3.4 的节点表。晚了（`late:*`）或有别的告警（某类地面失败率过半（楼梯地面看评估机器人的固定行，q ≥ 0.5 起）、带负载的比空载多摔 10% 以上、乘子顶到
   上限、力矩饱和、数值异常等），当时就查：先看 `run_report.py`，需要逐回合的失败原因再跑
   `scripts/unified/fail_probe.py`。
3. 找到原因就改新代码，从出问题之前最近的检查点续训（`RESUME_AT=<迭代>`），不从头来；只有改动影响到开局
   （观测、网络、第 0 步就生效的奖励）才从零开始。
4. 节点表按第一次完整训练的实际曲线重新标定。

## 5. 实施顺序

1. **指标库** `src/metrics/`：每只脚的接触状态机（踢立面、打滑、落脚位置、四脚着地，量法照
   `tools/go2_depth/acceptance/accept_stairs.py`），站立和平地指标；两个环境各写一个「台阶几何查询」。
   tinynav 的验收改成调用它（结果要和现在一致）。
2. **tinynav-sim 的机器人模型**按 unitree_ros 对齐。
3. **mjlab 验收 v2**：空载 0 kg / 负载两种条件，三个种子合并，按 2.2 判，报告写明随机化范围和空载 / 负载对比。
4. **机型表**：负载上限改成行走负载；关节静摩擦、阻尼随机化。
5. **老师 v2**：遮挡扫描模式、压缩的特权向量、约束用指标库。先用 Go2 一个种子做原型，和现在的统一老师比：训练中
   各项指标读数，以及蒸馏出的盲走学生踢立面的次数。不如两个老师（盲走老师 + 感知老师）就退回两个老师。
6. **学生**：蒸馏 + 微调，按三层验收。
7. 原型有效后推到六个机型。真机校准流程等用户下次跑真机时开始收集数据。
