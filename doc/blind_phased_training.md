## 2. 训练流程

### 阶段

| 阶段 | 任务 | 轮数 | 内容 |
|---|---|---|---|
| teacher | `Unitree-<R>-Blind-Teacher` | 0–5000 | 从零训练。地形里固定 8% 楼梯，其余平地和起伏地。跑偏、站姿、原地踏步等代价在 500–3000 轮内逐步加到全权重（腿式还要等机器人学会走路，见 mdp.staged_clock 的 walk_ratio） |
| 门槛 | — | 3000 / 4000 / 5000 | 平地验收（44 条指令、跑偏、原地转、停车、原地踏步复位、步态节奏、轮式四轮着地、不摔）。通过就进入 mixed；到 5000 都没过，就按配方修改流程处理，或按兜底规则从最好的 teacher 检查点进入 mixed |
| mixed（楼梯阶段） | `Unitree-<R>-Blind-Mixed` | teacher 轮数 → 11000 | 楼梯占比在 3000 轮内从 8% 升到 50%（stairs50），每 1000 轮完整验收一次。第一个全部通过的检查点进入精修 |
| polish（精修） | `Unitree-<R>-Blind-Polish` | +2000 | 楼梯占比固定 50%，熵系数减半（lowent 时 0.0025）。精修中途和结束各验收一次 |
| 验收用任务 | `Unitree-<R>-Blind-Scratch`（楼梯）、`Unitree-<R>-Blind-Flat-Scratch`（平地） | — | 和训练任务同一套机器人和观测，play 配置 |

### 配方 = 代码 + 开关

配方由代码和环境变量 `BLIND_PILOT`（逗号分隔的开关）共同决定。开关在导入时读取，所以要在启动 Python 之前设好。每个最终模型的开关列表在它目录下的 `blind_pilot.txt`。其他环境变量：

- `BLIND_ANCHOR_COEFF=0`：mixed / polish 不再把平地动作拉向 teacher（见第 3.4 节）。
- `BLIND_ANCHOR_CHECKPOINT=<teacher 的 .pt>`：mixed / polish 的 runner（PhasedAnchoredRunner）要求必须设置，系数为 0 时也会按严格匹配载入它。如果改了 actor 的输入维度，要指向一个同样加宽过的 checkpoint，或者换用 MirrorVelocityOnPolicyRunner（系数为 0 时两者等价）。
- `BLIND_PHASE_START_IT=<teacher 轮数>`：mixed 的楼梯占比从这一轮开始爬升（As2W 为 4000）。checkpoint 里存了 common_step_counter，接着训练时会恢复。
- As2W 从零训练时用 `--agent.seed=7`：seed 42 的 As2W 两次都没站起来，属于起步运气，不是配方问题。

命令示例（As2W；其他机器人换任务名和轮数）：

```bash
export BLIND_PILOT=$(cat /home/danny/blind_finals_20261029/as2w_mixed_7000/blind_pilot.txt) BLIND_ANCHOR_COEFF=0
# teacher（从零）
python scripts/train.py Unitree-As2W-Blind-Teacher --env.scene.num-envs=4096 --agent.run-name=phased_teacher \
  --agent.seed=7 --agent.max-iterations=5001
# mixed（从通过门槛的 teacher 检查点）
BLIND_ANCHOR_CHECKPOINT=$PWD/logs/rsl_rl/as2w_blind/<teacher run>/model_4000.pt BLIND_PHASE_START_IT=4000 \
python scripts/train.py Unitree-As2W-Blind-Mixed --env.scene.num-envs=4096 --agent.run-name=phased_mixed \
  --agent.resume=True --agent.load-run='^<teacher run>$' --agent.load-checkpoint='^model_4000\.pt$' --agent.max-iterations=7001
# polish（从 mixed 检查点 N，2000 轮）
python scripts/train.py Unitree-As2W-Blind-Polish ... --agent.load-run='^<mixed run>$' --agent.load-checkpoint='^model_N\.pt$' --agent.max-iterations=2001
```

训练机上原来的自动化脚本（phased_common.sh 的 teacher_run / mixed_run / polish_run、gen_gate.sh 门槛判定、accept_fast_small.sh 的快速验收、auto_polish.sh、judge_polish.sh、mx_pass.py）已经归档在 `/home/danny/blind_local/archive/` 的 `trainer_t1_text_20261029.tgz`（t1 上的 go2-blind 目录）、`trainer_t2_text_20261029.tgz` 和 `blind_local_text_20261029.tgz`（本机）。

### 验收

测试脚本在 `scripts/blind/eval/` 和 `scripts/go2_blind/eval_map3.py`、`eval_stairs.py`，表格和判分在 `scripts/blind/acceptance/`（accept_tables.py、gate_flat.py）。一个检查点的完整验收在 4090 上约 15–40 分钟，同一台机器一次只跑一个验收。

几个评测上的坑：
- **map3 不带操作员的 bug（10-28 修复）**：eval_map3 设置指令时，没关掉轮式 play 配置里 20% 的"带一点转向"指令，18/64 台走的是弧线，撞上扶手。10-28 之前轮式所有不带操作员的数字都偏低（As2W 的约 78% 主要是这个原因）。
- **停车测试只在一个步态相位停**：eval_standing 让所有机器人在 3.0 s 同时松杆，等于只测一个相位。B2 有一个很窄的弱相位，测到时侧向停车摔 8–16%，测不到时 0%。在 0–0.5 s 内扫相位（scratchpad b2fix/stop_phase.py，已归档）结果稳定得多。
- **种子噪声小**：同一检查点换种子，速度 ±1–2%，蠕动 ±0.1–0.2 cm，跑偏占比 ±0.6%。检查点之间的差别是真的，"第一个通过的检查点"带有训练轨迹的运气。最终选择都在 3 个种子上确认。

## 3. 轮式配方演变

版本号带 w 的是轮式。teacher 的问题在前面几版，mixed / polish 的问题在 v13 之后。每一行的"效果"都是对应门槛或检查点的验收结果。

### 3.1 teacher：先学会用轮子开（v1–v11，10-23 至 10-24）

| 版本 | 改动 | 原因 | 效果 |
|---|---|---|---|
| v1 / v2 | 统一的分阶段 teacher；v2 平地速度不足代价（flat_speed_deficit）加到全组 | 从零训练的统一配方 | Go2W / As2W 直行时小跑（四轮着地 2–27%），B2W 不抬腿但也不会横移 |
| v3 | 步态奖励从 10% 爬到 100% | 想让它先学会滚 | 无效，抬轮代价和 v1 一样 |
| v4 | 抬轮代价 -4 → -12；髋外撇代价只在零指令时算 | 对比滚和跑的奖励，跑在 1.5 m/s 赢 2.8/s | 一开始就 -12：As2W 早期大量摔倒，Go2W 故意触发非法接触结束回合 |
| v5 | 抬轮代价在 500–2000 轮从 -4 爬到 -12 | 避开 v4 的早死 | 仍然直行小跑 |
| v6 → v7 `wheelclock` | 轮子能开的指令（直行、\|wz\| ≤ 0.1）下步态时钟清零 | 发现是时钟观测在驱动小跑：不给奖励也跟着时钟跑 | Go2W / B2W 四轮着地 97–100%。As2W seed 42 没站起来，换 seed 7 正常 |
| v8 | 轮式加存活奖励 +4/s | v7 在 850–1900 轮崩溃：回报为负，策略故意结束回合 | 推迟崩溃到约 1900 轮 |
| v10 `liftflat` | 抬轮代价固定 -4，不再爬升 | 爬升让价值损失 0.4 → 1.0，动作噪声 0.8 → 1.3–1.5，越抖越抬轮，最后崩溃 | 不再崩溃；但 Go2W / As2W 又开始"慢慢抬轮"（每秒 0.5–1 次，120–290 ms，抬 1–2 cm） |
| v11 `grip` | 仿真摩擦改为椭圆摩擦锥、impratio 10（腿式之后也加了） | 根因：MuJoCo 默认金字塔锥 + impratio 1 时轮子在负载下慢慢向外滑，髋力矩变大，加上髋力矩代价后策略抬轮去重新放 | Go2W / B2W 四轮着地 100%。**部署注意**：sim2sim 场景也要用同样的接触参数 |
| v12（As2W） | `as2wwide` 站姿 -0.22；另试 `nohip`（去掉髋力矩代价） | As2W 用三个轮子开（一条腿收起），猜是 -0.38 的窄站姿 | 都没用；后来所有髋相关内容取消、髋默认 0（hipzero，10-24 用户决定）后 As2W 正常四轮着地 |

### 3.2 teacher：统一配方之后（v8w–v13w，10-25 至 10-27）

10-24 用户决定取消所有髋力矩相关内容（靠原地踏步散热），10-25 轮式按腿式的结果对齐：

- **v8w**：v11 去掉 marchhip、deficitfast，加上 marchquiet（踏步时 4 次推力跳过 3 次）、speedboth（平地速度两侧都罚，90–110%）、nohipload、lowent（熵减半）、arcclock（时钟按最快那只脚的速度）、hipzero（髋默认 0）、marchreset（踏步把歪掉的髋复位）、lowfric（训练摩擦对数均匀）、stairboth、stairline。
  - 效果：As2W 3000 / 4000 门槛不过：(1.0, 0, 0.1) 的转向只有指令的 19–56%。
  - 原因：|wz| ≤ 0.1 被当作"轮子能开"，只能靠差速转。
- **v9w** = v8w + `arcstep`（能开的转向上限 0.1 → 0.03，部署端时钟同步）+ `gaitw1`（步态奖励 ×2，修横移时钟）。
  - 效果：转向修好。新问题是横移时往后漂（1.5–2.2 cm/s），踏步后髋复位越来越差。
- **v10w** = v9w + `sidew6`（横移漂移代价 ×6）+ `marchreset2`（髋复位代价 ×2）。
  - 效果：Go2W 3000 横移漂移通过，4000 又出现，方向在检查点之间翻转。髋复位仍然差一点，失败的部分是踏步后站立的那 3 秒。
  - 横移漂移的根因：横移踏步时策略给轮子的目标速度约 0.6 rad/s，着地的轮子跟着滚，机身跟着走。
- **v11w** = + `stanceroll`（按测量到的着地轮速罚）。**失败**：着地轮速不完全由策略决定，代价噪声大，价值损失是 v10w 的 3 倍，2000 时 9 条速度不过。
- **v12w** = v10w + `steptarget`（踏步且没有前进指令时，罚轮子目标速度）。
  - 效果：横移漂移修好（每条横移指令偏移 ≤ 4%）。
  - 剩下斜向指令 (0.6, ±0.4) 的 y 方向只有 65–78%。
- **v13w** = + `diagaxis`。
  - 原因：平地速度代价只看沿指令方向的速度。x 108%、y 68% 合起来沿指令方向是 0.96 倍，在 0.9–1.1 之内，不扣分。
  - 改法：斜向指令按每个轴分别判。
  - 效果：斜向 x 95–97% / y 89–96%。Go2W、As2W 都在 4000 通过门槛。As2W 的最终模型就来自这个 teacher；Go2W、B2W 后来为了 riserprox 和停车蠕动又从零训练了 teacher（v13wd–v13wh）。

### 3.3 B2W 的停车蠕动（v13wb–v13wj）

B2W 是最重的轮式（82 kg）。门槛一直卡在停车后的蠕动：松杆后机身在刹住的轮子上慢慢滑，4 秒内 1–5 cm（门槛 1 cm）。

| 版本 | 改动 | 原因 | 效果 |
|---|---|---|---|
| v13wb | `marchgait3`（踏步时步态奖励 ×3）+ `standlongw`（零指令保持 4–8 s，原来 2–5 s） | B2W 叫它踏步时蹲在四个轮子上不动；站着白得 56% 的支撑相奖励 | 踏步修好（1.0–1.2 次/s，髋复位 6.9° → 1.4°）；3000 蠕动 2.1–7.6 cm，4000 为 2.5–3.6 cm |
| v13wc | `standw4w`（站立位置保持代价 ×4） | v13wb 停车后腿回到默认姿态，刹住的轮子不动，机身被推着走 6–20 cm | 不到 2 小时就被 v13wd 取代，没有门槛结果 |
| v13wd | 全组：`riserprox` 从 teacher 起 + `stairshare` | 见第 3.4 节 | 4000 后退停车蠕动 2.9 cm；5000 为 1.3–1.7 cm，且有 2 次摔倒 |
| v13we | 全组 `drivepose`：轮子能开的指令下，腿用站立的姿态容差（不是走路的） | 根因：开车时腿在走路容差下倾斜（Go2W 前大腿 -12.6°，B2W 后大腿 +13°），停车后被站立容差拉回，2–6 s 内机身在刹住的轮子上滑 | B2W 2000–4000 蠕动卡在 1.3–1.4 cm |
| v13wf | `drivepose2`：开车时容差减半 | 继续收紧 | **失败**：指数核在离默认远的地方梯度反而变平，B2W 蹲得更深（小腿 -13° / -21°），蠕动 3.9 cm。已删 |
| v13wg | `drivequad`：开车时按腿偏离默认的平方罚（-2） | 换成不会变平的二次代价 | 蠕动修好（Go2W ≤ 0.54 cm），但 B2W 3000 摔了 86 次：上一步动作作为观测形成正反馈，部分机器人的动作每步放大 3 倍直到失控；动作裁剪救不了 |
| v13wh | `drivelp`：同样的二次代价，但用 0.5 s 低通后的偏离 | 去掉逐步的高增益 | 不再失控；3000 门槛只差蠕动（1.4–2.0 cm）。4000 更差，停掉，按兜底规则从 teacher 3000 进入 mixed |
| v13wi | `legkp15`：腿 kp 160 → 240、kd 5 → 6（仅试验） | 根因实验：1 s 后冻结动作，kp 160 时机身下沉滑动 3–21 cm、部分摔倒；kp ×1.5 时 0.3–0.9 cm。说明 kp 160 下 B2W 的站姿不能被动稳定，靠策略一直在调 | 被动下沉没了，但 1000–2000 的蠕动 0.18–3.28 cm 不比 v13wh 好：剩下的是停车后策略还在重新摆姿态（和目标变化的相关系数 0.84–0.91），加上约 1 cm 的慢沉降。2000 时停掉。已删 |
| v13wj | `legkp15` + `standtgt`（轮式整组，-10）：零指令站稳后，腿的位置目标（1 s 低通）偏离站稳时的值就罚（仅试验，10-29 本机） | v13wi 剩下的是策略停车后还在重新摆姿态，直接罚目标的变化；用低通避免第 5.6 条的正反馈 | 从精修 7000 在 Polish 任务上微调 500 轮：停车蠕动最大 2.68 cm（前进 1.5），前进 1.0 为 2.48 cm，不比最终模型（1.97–2.19）好；目标变化（前进 1.0 后 4 s 共 5.2°）也没减少，代价在训练中只从 -0.20 降到 -0.16。没有达到 1 cm，所以没有从零训练 teacher。对照组（只有 legkp15）跑到 7180 轮时被系统因内存不足停掉，没有结果 |

B2W 最终 = v13wh：mixed 6000 → 精修 7000，蠕动 1.97–2.19 cm。

### 3.4 mixed：上楼梯（v13w 之后）

- **teacher 锚定取消**（`BLIND_ANCHOR_COEFF=0` + `stairs50`）：
  - Go2W 带锚定的 mixed 6000 每一档台阶都上不去（卡在第一级前，四轮着地），和腿式 v8b 一样。
  - 腿式试过所有形式的平地锚定，都让上楼变差：盲走机器人看不到台阶，平地上也得用能上楼的步态，teacher 的平地步态不是。
- **`riserprox`**（Go2W 先试，后来全组从 teacher 起都开）：
  - 问题：取消锚定后 Go2W 仍然 0% 上楼。前轮在第一级前 0–10 cm 处只推 20 N（体重 45 N）。"轮子被台阶挡住"的触发条件要求 \|F_xy\| > 1.2\|F_z\|，只有 1–3% 触发，抬轮奖励几乎为 0。
  - 改法：只要轮子靠近一个比它最佳落脚点高 4 cm 的台阶，就算被挡住。
  - **结论**：Go2W / B2W 的上楼是在 mixed 后期才出现的，楼梯占比超过约 0.4 之后 foothold 奖励才开始涨。Go2W mixed 6000 还是 0%，8000 已经约 92%。不要因为第一次楼梯检查没过就停掉 mixed，要看 foothold_height_gain 的趋势。
- **`stairshare`**（全组，从腿式 B2 借来）：
  - 问题：在楼梯上，跑偏代价只算朝向，宽的机器人在没有操作员时会侧滑撞上扶手。
  - 改法：楼梯上把"侧向偏移占行走距离的比例"也算进去。
- **`stairhead`**（全组）：楼梯上跑偏代价的朝向部分改用观测到的朝向误差，上限放宽。
  - 当时的诊断针对的是 As2W 不带操作员约 78% 的问题，后来查明那主要是第 2 节的评测 bug。这个开关保留没有撤掉（不来回改）。
- **`slowarc`**（Go2W / B2W 的 v13wf 起）：带转向的指令最低速度从 0.3 降到 0.1 m/s。
  - 原因：轮式只在弧线和横移时才迈步。慢弧线在训练指令里只占 0.24%，稳定地慢约 0.03 m/s，正好卡在 80% 门槛上。
  - As2W 的最终模型没有这个开关（它的 teacher 早于这个改动）。

三台轮式在 mixed / polish 的结果：

- **As2W**（teacher v13w 4000 → mixed v13we）：
  - 7000 只差上楼速度 0.799（门槛 0.80）。
  - 8000 横移漂移 6.0%；9000、11000 各差 3 项；10000 硬性项不过。
  - 精修 9000 在种子 0 上全过，但种子 1 平地摔 1 台、种子 2 楼梯摔 1%。
  - 按兜底规则选 mixed 7000。

## 5. 轮式已知问题和根因

1. **B2W 停车蠕动（约 2 cm，门槛 1）**：
   - kp 160 / kd 5 下，82 kg 的 B2W 小腿下沉约 14°，站姿不能被动稳定。
   - 加大刚度（legkp15）能去掉被动下沉。剩下的是停车后策略还在重新摆姿态，加上约 1 cm 的慢沉降。
   - 轮子的驻车刹车加到 3–10 倍没有区别。
   - 腿刚度也影响部署：deploy.yaml 里的增益要和训练一致。
2. **Go2W 蠕动（约 1.0 cm）和下楼速度（约 0.80 倍）**：都正好在门槛上。精修越久蠕动越大（12000 → 13000）。
3. **As2W 上楼速度（0.79 倍）和慢速弧线**：As2W 的配方停在 v13we，没有后来的 slowarc、drivequad / drivelp。
4. **慢速弧线普遍偏慢约 0.03 m/s**：
   - 轮式只在弧线和横移时迈步，所以只有最慢的弧线会掉到 80% 以下。
   - 腿式同样的指令是 98–107%（腿式的前进全靠迈步）。
5. **横移时往后漂**：
   - steptarget 修好了主要部分。
   - 剩下的部分是迈步本身的偏差：轮子目标置零也还在。
   - 盲走 actor 看不到机身速度，可能是可观测性的极限。
6. **上一步动作的正反馈**：
   - 刚度高、逐步计算的姿态代价（drivequad）会让策略把自己的动作噪声抵消掉，环路增益变大，部分机器人在复位后失控。
   - 改用低通（drivelp）后不再失控。
   - 加新的姿态或站立代价时要注意这一点。
7. **第一代轮式（真机上现在跑的那批，10-20 前后）**：
   - Go2W v5 右转弱于左转（小弧线左 100%、右 87%），0.2 m/s 只到约 70%。
   - 当时提出过的修法：更多 0.1–0.3 m/s 指令，镜像数据增强。这些都没在第一代上做。新配方的 slowarc 和镜像损失针对的是同类问题。
8. **接触求解器（go2-depth 10-29 在 tinynav-sim 里测的）**：
   - 轮式训练用的是 grip 设置：elliptic 摩擦锥，impratio 10。tinynav-sim 现在按 ONNX 元数据给每个策略设求解器。
   - 换成 pyramidal、impratio 1 时，站立 6 秒轮子会向外滑开 2–4 cm。
   - 所以仿真里跑轮式策略，求解器要和训练一致。
   - Go2W polish 12000 已装到用户的 Jetson 上（blind_v1，带 gait_phase 观测）。dry run 正常，还没上真机。

### 8.1 流程变化

### 8.3 腿式 feetedge（10-30 晚上）
- 参考 Extreme Parkour 的 feet_edge：`feetedge` 给每只脚一个世界坐标对齐的 3×3 射线网格（±4 cm），高差 > 3 cm 或有射线落空算"在边缘"，在楼梯环境里对着地的脚计代价，权重 -1（mdp.feet_edge）。
- 诊断（tools/foot_edge_diag.py，金字塔楼梯 0.5 m/s）：交付的腿式模型站在边缘 17–19% 的支撑时间（接近随机）；踢立面约 0.1% 的接触；下 12–18 cm 台阶时小腿碰地 5–6% 的时间。
- Go2 精修对比（从重启点 mixed 7000 精修到 8000）：

| 配方 | 站在边缘 | 腿碰地 | 摔倒（512 台） | 楼梯阶段验收 |
|---|---|---|---|---|
| 原配方（交付的 8000） | 17.5% | 2.2% | 0 | 不过：步态节奏 |
| feetedge -1 | 17.8% | 1.5% | 0 | 不过：步态节奏 |
| feetedge -3 | 15.0% | 2.6% | 5 | 不过：摔倒、平地速度、步态节奏 |
| feetedge -1 + legcons | 17.1% | 1.1% | 0 | 通过 |

  盲走看不到边缘，代价基本改不了落脚点，主要减少小腿碰地；-3 会摔，放弃。
- **约束（legcons，mdp.adaptive_constraints）**：验收项作为约束，每项一个拉格朗日乘子 λ，按训练中测到的值（指数平均，时间常数 1000 步）每 24 步更新：λ ← clip(λ + lr × 差距, 0, max_scale - 1)，对应奖励项权重 = (1 + λ) × 原权重。目标按 tools/cons_calib.py 标定（训练中的值比验收高 3–8 个点）：横移步态吻合 ≥ 0.89（foot_gait，≤ 3 倍）、横移跑偏 p90 ≤ 0.06（side_drift，≤ 3 倍）、站在边缘 ≤ 0.10（feet_edge，≤ 2 倍）、腿碰地 ≤ 0.015（leg_ground_contact，≤ 3 倍）。Go2 试验里横移步态吻合 0.80 → 0.89、腿碰地 2.2 → 1.5%，边缘和跑偏没到目标。
- **正式训练**：三台从各自通过门槛的 teacher 3000 起跑 mixed（交付配方 + feetedge），平均模型判定；精修加 legcons（polish/run_mx_R.sh）。约束只放在精修：mixed 已经在跑，加进去就要从 teacher 重来；目标按快训完的模型标定，mixed 前期所有约束都会顶到上限，等于把代价一下子放大 2–3 倍（feetedge -3 的教训）。
- **t2 两次崩溃**：训练机开了 CUDA MPS，一个进程的致命错误（Warp CUDA error 700）会让同一张卡上所有进程一起退出。19:27 是旁边跑 2048 台的标定，21:49 是一次验收的 6 个评测同时启动（停车、跑偏改成 256 台后显存更大）。之后：同卡两个训练时验收评测一个一个跑（accept_fast_small.sh / final_seeds.sh 的 ser）；崩溃后的训练可能以 0 退出，自动续训改成只看最新检查点是否到终点；mixed_run 可以从崩溃点续训（FROM_RUN FROM_N），MX_RAW_CHECKS=0 关掉单检查点验收。

### 8.5 B2 的两个根因（10-31 至 11-01）

- **侧停摔倒 → `stopside`**：stop_trace.py 显示只在从 vy +0.6（向左）停车、且停在验收用的相位时出现：左边两只脚着地、右边两只脚抬着，1–2 s 后侧翻。训练里这种停车每 64 条平地指令才约 1 次。`stopside` 把 velocity_command 的 fast_side_prob 0.15 改成约 1/12。侧停摔倒 3–5/256 → 0/256。
- **1.5 rad/s 起转摔倒 → `yawslew`**：
  - `spinup`（站立起转比例 1/89 → 约 1/13）没用。
  - spin_trace.py（mixed 平均 9000）：0.12 s 内就到 1.5 rad/s 的 80%，此时单脚着地，0.1–0.3 s 内横滚 16–26°，4096 次摔 7 次。评测时给指令加 0.5 s 斜坡就 0/4096。
  - `yawslew`：track_angular_velocity 的参考角速度上升率 ≤ 3 rad/s²（mdp._yaw_reference），下降立即跟。只改奖励，actor 和部署不变。
  - 从 teacher 3000 重训 mixed，1000 轮后摔倒 0/4096，最大倾斜 47° → 15–16°。mixed 平均 5000 在 3 个种子上全过（蠕动 ≤ 0.48 cm），交付。
- 精修会提高左转起转的摔倒率（2048 次/方向：mixed 6000 为 0，精修 9000 为 3），所以 B2 不精修，直接交付 mixed 平均。

### 8.6 B2W：停车蠕动 → 腿部停车保持，精修和交付（11-01）

B2W 的门槛一直卡在停车后的蠕动（门槛 1 cm）。冻结试验：停车 2 s 后把动作固定，蠕动只有 0.12–0.32 cm。所以不是被动下沉，是策略停车后还在重新摆姿态。

| 版本 / 试验 | 改动 | 原因 | 结果 |
|---|---|---|---|
| v13wn（从零） | `legkp15`（腿 kp 160 → 240、kd 5 → 6）+ `standtgt`，10-29 删掉后重新加回 | 先排除腿软 | 门槛 3000 / 4000 / 5000 只差蠕动（5000：前进 1.0 2.88、1.5 m/s 2.10、弧线 1.86 cm） |
| `standtgt` ×4 / ×10 试验 | 加大目标保持代价 | 罚重一点能不能压住重新摆姿态 | 前进变好，后退变差，刹停 0.73 s → 2.1–2.6 s（策略为了少罚而慢刹）。光加权重不对 |
| v13wo `restlock`（从零） | 停稳之后，姿态项以停稳时的姿态为目标，不再往默认姿态拉 | 姿态项在停稳后还在拉腿 | 门槛 3000 / 4000 / 5000 都没过，5000 后退 1.0 蠕动 6.50 cm |
| `lockfix` 试验 | standing_target_hold 的锚点改为锁定后 0.5 s 的平均目标；critic 加锁定偏移观测（mdp.standing_lock_offsets） | rew_attr2.py（训练奖励）：停车 2 s 后冻结每秒多拿 0.25–0.65，奖励是对的；但原锚点滞后，静止每秒亏 0.8–1.1 | 有好有坏：前进、弧线变好，后退、转向变差 |
| `standclock` 试验 | actor 加"零指令持续时间"观测（mdp.stand_time） | back_trace.py：轮子 0.5 s 内刹住，之后约 5 s 机身在刹住的轮子上慢慢往后滑；怀疑 0.2 s 历史分不清"刚停"和"站着" | 600 轮后没有改善 |
| v13wq `leghold20` | 动作层的腿部保持（下面） | 奖励对、观测够，但策略学不会保持 | 不重训。v13wo 平均 5000 加保持过了门槛：44/44，蠕动 ≤ 0.47 cm（之前 6.5） |

- **腿部保持**（mdp.HeldJointPositionAction，开关 `leghold20` / `leghold` / `leghold10` = 2.0 / 1.5 / 1.0 s，apply_leg_hold）：
  - 锁定：零指令（且不在踏步）持续 hold_after_s，并且所有腿关节 < 0.1 rad/s 时，把腿的目标位置固定在当时的值。
  - 松开：有指令、踏步、或任一腿关节 > 1 rad/s（被推）。
  - 和轮子刹车（BrakedJointVelocityAction）是同一个思路。
  - 时间：1.0 s 太早（横移 1.16 cm 不过），1.5 s 后退 0.92 cm 太险，2.0 s 全部 ≤ 0.6 cm。
  - 训练任务和评测任务都要加（b2w/blind_env_cfgs.py 调用 apply_leg_hold），否则评测的不是部署时的行为。
- **部署**：
  - deploy.yaml 的 actions.JointPositionAction 带 hold_after_s / hold_speed / hold_release_speed（export_deploy_yaml.py 写入）。
  - 部署端 joint_actions.h 的 JointPositionAction 实现同样的逻辑。真机必须用这个版本的部署代码，否则停车后会蠕动。
