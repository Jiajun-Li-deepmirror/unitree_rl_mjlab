# 验收标准（2026-11-10 起执行）

六个机型（Go2、As2、B2、Go2-W、As2-W、B2-W）的盲走策略和深度学生共用一份标准。只在物理上确实不同的地方按机型区分：
负载上限、腿式 / 轮式各自的项目。其余门槛对所有机型一样。代码：mjlab 判定 `scripts/blind/acceptance/accept_tables.py`、
`jobs/fe_pass.py`、`jobs/luck_pass.py`，训练链 `jobs/blind_chain.sh`、`jobs/fe_chain.sh`，tinynav 判定 `tools/go2_depth/acceptance/`。
这一轮剩下的检查和之后的干净复现都按它判。

## 1. 通过的定义

- 一个模型通过 = mjlab 验收 3 个随机种子（0 / 1 / 2）全部通过 + tinynav 验收通过。
- 运气通过（自动，`jobs/luck_pass.py`）：3 个种子里最多 1 个种子不过，且它不过的项目只有摔倒、所有测试合计只摔了 1 台（平地速度、跑偏、停车、交替原地转、负重站立 3 s 以后、原地踏步和复位、四轮着地、楼梯；2026-11-11 起全部计入，之前漏了负重站立、踏步、四轮着地三项。急停后起步只判站姿，它的摔倒不计入）；
  另外两个种子全过 → 记为通过，日志写明是哪个种子。

## 2. mjlab 验收（每个种子）

指令一律按 2 m/s²（vx、vy 合起来）和 3 rad/s² 斜坡给，同真机控制器和 tinynav-sim（2026-11-10 起全部机型）。

| 项目 | 内容 | 门槛 | 现状 → 建议 |
|---|---|---|---|
| 平地速度 | 44 条指令（前后、横移、斜向、转弯、弧线），每条 32 台 | 实际 / 指令在 80–120%，0 摔 | 统一，不变 |
| 跑偏 | 直行和横移 10 s，256 台 | 航向偏差中位数 ≤ 3°、p10 / p90 ≤ 8°；横向偏移 p10 / p90 ≤ 行进距离的 5% | 统一 5%（B2-W 原 5.2%） |
| 原地旋转 | ±0.5 / 1.0 / 1.5 rad/s，256 台转 10 s | 终点离起点 p90 ≤ 0.2 m（2026-11-11 文档改为代码一直用的 p90，原写「中位数」） | 统一，不变 |
| 交替原地转 | 左右交替 8 次再站 2 s | 终点离起点中位数 ≤ 0.25 m，0 摔 | 统一 0.25 m（原来每台不同：B2 0.17、Go2-W 0.29、As2 0.30、As2-W 0.31、B2-W 0.28 m） |
| 负重站立 | 负载上限下站立，3 s 后 | 0 摔 | 统一，不变 |
| 停车 | 各方向松杆停车 | 站稳离地 ≤ 1%，停后 4 s 蠕动 ≤ 1 cm，1.0 m/s 刹停距离 ≤ 30 cm | 统一，不变 |
| 原地踏步 | 髋外张 8° 起步，站 3 s、踏步 5 s、再站 3 s | 每只脚每秒落地 ≥ 0.5 次；髋最后复位到 2° 以内；踏步 5 s 漂移 ≤ 5 cm；0 摔（2026-11-11 文档改为代码的判法，原写「2 s 内复位」） | 统一，不变 |
| 步态节奏 | 速度时钟 | 判定的指令全部合拍 | 统一，不变 |
| 楼梯 | 5–18 cm 各档上下楼 | 有操作员 ≥ 95%、无操作员 ≥ 90%、上下楼速度 0.8–1.2 倍、停稳 ≥ 95%、停住四脚着地 ≥ 90% | 统一，不变 |
| 四轮着地（轮式） | 前进后退 | ≥ 98%，0 摔 | 统一，不变 |
| 摔倒 | 平地、楼梯、跑偏、停车 | 0 | 统一，不变 |
| 负载停车站姿 | 负载上限、1.5 m/s 急停后站 3 s | 腿关节偏离默认站姿 p90 ≤ 0.15 rad（同真机踏步复位的触发线） | 新增考核（原来只记录） |
| 髋负载 | 站立 / 1 m/s 时髋力矩 | 不考核 | 不变 |

## 3. tinynav 验收（在 tinynav-sim 里，用导出的 ONNX）

| 项目 | 腿式 | 轮式 | 现状 → 建议 |
|---|---|---|---|
| 楼梯（map3 + 金字塔） | 踢台阶 ≤ 2 次/趟、落脚居中 ≥ 80%、踩边 ≤ 10%、打滑 ≤ 0.2 次/趟、0 摔 | 滑回 ≤ 5%、起步平台空踏 ≤ 0.5 次/趟、上楼航向偏差平均 ≤ 3°（一直在判，2026-11-11 补进文档）、0 摔（顶部平台见下一行） | 统一原始门槛（B2 原来放宽到已部署模型水平：3.1 次、76.6%；负载 4.2 次、73.9%、打滑 0.6） |
| 顶部平台踏步（轮式） | — | ≤ 1.0 次/趟 | 只用 `slide_gate.sh` 的 map3 L0 12 趟量；轮式盲走也跑（原来只有深度学生）；`accept_stairs` 的顶部空踏改为只记录（两种量法原来不一致：Go2-W 0.5 和 2.8） |
| 滑回门（轮式） | — | map3 L0 12 趟（接近时再 12 趟）滑回 ≤ 5% | 统一，不变 |
| 负载 | 负载上限、前角点：0 摔 | 同左 + 滑回 ≤ 5% | 统一，不变（B2 的 x 0.30 角点只记录） |
| 横滚 | ≤ 6° | ≤ 4° | 只记录（门槛没标定，所有已部署模型都超） |
| map3 18 段、上楼姿态 | 只记录 | 只记录 | 不变 |

负载上限（物理差异，保留）：Go2 / Go2-W 12 kg、B2 / B2-W 40 kg（官方数据）；As2 10 kg、As2-W 13 kg（没有官方数据，按约一半体重，用户 2026-11-11 定）；位置前 0.15、上 0.20 m（B2 / B2-W 上 0.30 m；B2-W 的 tinynav 负载 2026-11-11 前误用前 0.30 m，已改）。

## 4. 训练链各阶段的门槛

| 阶段 | 门槛 | 现状 → 建议 |
|---|---|---|
| 盲走 T（平地老师） | mjlab 平地各项，种子 0 | 到上限（配方 RECIPE_T_MAX，默认 5000）都没过时，自动用最后一个检查点进入 M（2026-11-10，同 M→P），由 P 的完整验收把关 |
| 盲走 M（混合） | mjlab 全项，种子 0；只差上下楼速度时算过 | 到上限都没过时，自动用最后一个检查点进入 P（这一轮 Go2、As2 是人工交给 P 的） |
| 盲走 P（打磨） | 第 1 节的「通过」 | 不变 |
| 深度老师 | mjlab 全项 + 顶部平台抬轮时间占比 ≤ 22%（轮式） | 写进配方，不再手调 |
| 深度学生 | 第 1 节的「通过」 | 不变 |

检查分两档（2026-11-11）：每个种子先跑平地各项（约 5 分钟），通过了再跑 map3 和分档楼梯（约 12 分钟），用两档的结果一起判；
P 和深度学生的 3 个种子逐个这样跑，全部通过才发 tinynav 请求。平地没过但只差一次摔倒时（运气规则可能适用）也跑楼梯档。
T 只跑平地档（跑偏不判）。`jobs/fe_check.sh` 的 `FE_CHECK_PART=flat|stairs`。

## 5. 干净复现：四轮（2026-11-10 起）

每个机型只用 `jobs/recipes/<机型>.sh` 的配方，从零跑，中间不做人工修正。入口 `jobs/full_chain.sh 机型 TAG 轮次`，
排队 `jobs/repro_queue.sh TAG 机型:轮次 ...`，日志 `logs/jobs/repro_<机型>.txt`、`logs/jobs/repro_queue.txt`。

| 轮次 | 内容 | 门槛 |
|---|---|---|
| 1. 盲走 `blind` | 六个机型的盲走链 T → M → P，通过后打包 | 第 1 节的「通过」（3 个种子 + tinynav） |
| 2. 深度老师 `teacher` | 基于第 1 轮的盲走包，加上地形扫描输入继续训练老师 | mjlab 检查，带速度余量（腿式 0.05、轮式 0.08；没有余量的不算过，不再退而取余量最大的）；轮式另有顶部平台抬轮时间 ≤ 22% |
| 3. 学生第一阶段 `s1` | 从零蒸馏（`RECIPE_S1_ITERS` 6000 步，学习率 `RECIPE_S1_LR`） | 不单独检查；日志记下蒸馏损失的走势 |
| 4. 学生第二阶段 `s2` | PPO 微调，通过后导出 | 第 1 节的「通过」 |

- 一个机型的下一轮，只在它上一轮通过之后开始（没通过时排队里的下一轮自动跳过）。
- 某一轮不过：改配方，用新 TAG 从配方改动所在的最早阶段开始重跑（2026-11-11），不续训修补：
  - 它之前没改的阶段沿用已通过的结果，它之后的阶段全部重跑；只改步数上限（如 `RECIPE_M_ITERS`）时从这个阶段开始，不重训前面的阶段。
  - 每个 TAG 跑的配方存成 `logs/jobs/recipe_<机型>_<TAG>.sh`，`jobs/recipe_stage.sh` 比较它和现在的配方，给出最早改动的阶段：
    T（`RECIPE_BLIND_TM`、`RECIPE_BLIND_CONS`、`RECIPE_T_MAX`）、M（`RECIPE_M_ITERS`）、P（`RECIPE_BLIND_P`、`RECIPE_P_ITERS`）、
    深度老师（`RECIPE_DEPTH_*`、`RECIPE_TOPFLAT`）、学生第一阶段（`RECIPE_S1_*`）。
  - 盲走轮用 `REPRO_BLIND_FROM=M@旧TAG`（沿用 T）、`P@旧TAG`（沿用 T 和 M）或 `auto@旧TAG`；深度各轮用 `REPRO_BLIND_TAG`（沿用盲走包）
    和 `REPRO_FROM_TAG`（学生第一阶段沿用老师，第二阶段沿用老师和第一阶段）。
  - 沿用的结果在日志里写明来自哪个 TAG（`logs/jobs/repro_<机型>.txt`、`blind_<机型>.txt`）。
- 一台 GPU 跑完自己那批的这一轮，就接着跑它的机型里已经具备条件的下一轮，不等另一台。
- 每个盲走包有自己的加宽起点（`blind_init_<包名>`），不和旧包共用。
- 盲走各阶段的步数上限写在配方里：`RECIPE_T_MAX`（默认 5000）、`RECIPE_M_ITERS`（默认 5000）、`RECIPE_P_ITERS`（默认 2000），
  每个阶段在第一次通过时就停。一个机型重跑后，它后面几轮在队列里写成 `机型:轮次@新TAG`，
  或者把新 TAG 写进 `logs/jobs/repro_tag_<机型>`（已经在跑的队列也跟着用）。
