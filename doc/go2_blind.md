# Go2 盲走策略（blind_v0）

只用本体感知、不看地形的 Go2 速度策略：
- 遥控器全向移动，原地转向时踏步而不是扭身体；
- 零指令时站住不动；
- 正向上下 18 cm 以内的楼梯，可以在楼梯中间停住。

用仓库自带的 C++ deploy 部署到真机。

发布的模型是 `deploy/robots/go2/config/policy/velocity/blind_v0/exported/policy.onnx`，由下面「复现训练」的流程训练到第 20000 次迭代得到。

最初的设计计划见 [go2_blind_plan.md](go2_blind_plan.md)。

## 策略接口

| 项 | 内容 |
|---|---|
| actor 观测 | 角速度、重力投影、指令 (vx, vy, wz)、步态相位、关节位置、关节速度、上一步动作，共 47 维 × 10 帧 = 470 维（ONNX 输入 `obs` [1, 470]） |
| critic 观测 | 以上各项，加线速度、地形扫描、足端高度和接触力（只在训练时用） |
| 动作 | 关节目标角 = 默认角 + 0.25 × 动作；关节顺序 FL、FR、RL、RR，每条腿 hip、thigh、calf |
| 控制 | 50 Hz，kp 20 / 20 / 40，kd 1 / 1 / 2（hip / thigh / calf） |
| 指令范围 | 摇杆推满对应 vx −1.0 ~ 1.5 m/s、vy ±0.6 m/s、wz ±1.5 rad/s；三维指令的范数 ≤ 0.1 时按零处理 |

## 任务

| 任务 | 地形和用途 |
|---|---|
| `Unitree-Go2-Blind-Flat` | 只有平地，用来快速检查遥控手感；不在发布模型的训练流程里 |
| `Unitree-Go2-Blind-StageA`、`Unitree-Go2-Blind-StageB` | 复现用：发布模型前两个训练阶段的奖励组合 |
| `Unitree-Go2-Blind` | 平地、起伏地、上下楼梯，完整奖励 |
| `Unitree-Go2-Blind-Map3` | 在 `Unitree-Go2-Blind` 的基础上，加入仿 map3 楼梯间的带墙窄楼梯，用来微调 |

## 环境

按 [setup_zh.md](setup_zh.md) 装好 conda 环境（Python 3.11），然后 `pip install -e .`。

`setup.py` 固定了 mjlab 1.2.0、mujoco 3.5.0、mujoco-warp 3.5.0 和 warp-lang 1.12.1，换版本可能复现不出来。

4096 个环境可以在 16 GB 显存上跑，配置里已把 `ccd_iterations` 降到 50、`njmax` 降到 300。

## 复现训练

一条命令按顺序跑完四个阶段，RTX 5060 Ti 上大约 20 小时：

```bash
bash scripts/go2_blind/train_release.sh
```

每个阶段都从上一阶段的 checkpoint 续训：

| 阶段 | 任务 | 迭代 | 相比上一阶段的变化 | 为什么加 |
|---|---|---|---|---|
| A | `Unitree-Go2-Blind-StageA` | 0 → 6000，从零开始 | — | — |
| B | `Unitree-Go2-Blind-StageB` | 6000 → 9000 | 加 `foot_terrain_clearance`（−40）；不平地面上摆动腿高度只罚抬不够 | A 结束时下楼已经学会，但 12 cm 以上的台阶上不去：机器人在台阶前用平地的 9 cm 抬脚高度原地踏步 |
| C | `Unitree-Go2-Blind` | 9000 → 18000 | 加 `foothold_height_gain`（+2.0）；开始前把动作噪声 std 乘 1.5 | 卡在高台阶前时，原地停和往后退得分差不多，机器人会后退 |
| D | `Unitree-Go2-Blind-Map3` | 18000 → 20000 | 加带墙窄楼梯和走廊保持指令、平地慢速指令、下楼进度奖励；熵系数从 0.01 降到 0.005 | map3 的 0.19 m 窄踏面，以及平地低速追踪不足 |

**中断后接着跑**：

```bash
bash scripts/go2_blind/train_release.sh C
```

参数是从哪个阶段开始。脚本会自动找最新的 `*_release_b` 目录。

**每个阶段结束后检查一下**：

```bash
tensorboard --logdir logs/rsl_rl/go2_blind
```

- 看总奖励、动作噪声 std 和 value loss。
- 原来的阶段 C 跑过 19100 次迭代后开始发散：奖励从 37.5 掉到 16，动作 std 从 0.50 涨到 0.62，value loss 涨了 6–10 倍。所以流程只用到 18000。
- 如果你的阶段 C 在 18000 之前就这样，用发散前最后一个正常的 checkpoint，并跑一遍 `check_action_spike.py`。

**随机性**：种子（42）和环境数（4096）由脚本固定，不要改；环境数会改变每次更新的 batch 大小。GPU 上的物理仿真不是逐位确定的，所以复现出的模型不会和发布的完全相同，评估结果应在下面结果表的误差范围内。

**和原始训练的一致性**（发布前核对过）：
- 当前代码为四个阶段生成的环境和训练参数，和原始四次训练保存的 `params/*.yaml` 一致。唯一的差别是后来新增、默认关闭的指令选项。
- 种子 42 下，当前代码的 `StageA` 和原始阶段 A 的代码（提交 e0af9d6）采样出的指令和重置位姿逐位相同。
- `scripts/go2_blind/scale_action_std.py` 生成的 checkpoint，和原始的 `model_9000_explore.pt` 逐位相同。

## 导出和部署

1. **导出 ONNX**：脚本会顺带用 20 步 × 64 个机器人对比 ONNX 和 torch 的输出。

   ```bash
   python scripts/go2_blind/export_onnx.py $C --out deploy/robots/go2/config/policy/velocity/blind_v0/exported
   ```

2. **编译**：Go2 的板子是 aarch64，要在机器人上编译。

   ```bash
   cd deploy/robots/go2 && mkdir -p build && cd build && cmake .. && make -j
   ```

3. **运行**：上真机前先用 unitree_mujoco 做一遍仿真部署（见 README 第 4.5.1 节），然后运行 `./go2_ctrl --network=<网卡>`。

4. **遥控器**：

   | 当前状态 | 按键 | 切换到 |
   |---|---|---|
   | Passive | LT + 上 | FixStand（站起） |
   | FixStand | RT + A | 策略控制 |
   | 任何状态 | LT + B | Passive（阻尼） |

   左摇杆前后、左右分别是 vx、vy，右摇杆左右是 wz。

**部署端的保护**（只改了 Go2，共用代码和其他机器人不受影响）：

- **动作截断**：`deploy.yaml` 里的 `clip` 把关节目标角限制在默认角 ±2.0 rad 以内。
  - 正常运行几乎碰不到：训练条件下只有 0.004% 的步会被截，作用是拦住异常输出。
  - 观测里的 `last_action` 仍是截之前的值，和训练一致。
- **摔倒检测**：`deploy/robots/go2/src/State_RLBase.cpp` 里，机身倾角超过 1.0 rad（57°）就自动切到 Passive。
  - 仿真里走楼梯时，每次的机身最大倾角一般在 30° 左右，最大到 43–50°。
  - 训练条件下（带推力），倾角超过 57° 的 91 次里，有 88 次随后确实摔倒。
  - 共用的 `isaaclab::mdp::bad_orientation` 仍是空实现，所以其他机器人没有这个检测。

## 已知不足

- **下楼偏慢**：map3 的 L0 下楼按原定时长（指令 0.4 m/s、9 秒），平均只下降约 1.8 m，只有约 5% 能下够 2 m；时长放宽到 1.6 倍后是 100%。
- **窄踏面后的陡段会磕下巴**：map3 的 L0_07 是 0.19 m 的窄踏面，后面两级台阶连成约 37° 的陡坡，下巴的碰撞球（`base3_collision`）会碰到下一级台阶的立面。map3 上的重置大多是这个原因。
- **零指令下会被推倒**：训练条件下（2048 个机器人 × 40 秒）约有 25 次。
